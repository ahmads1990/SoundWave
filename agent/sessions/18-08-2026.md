## [23:19:00] Phase 1.5 — Albums & Tracks Catalog Module (Backend)

**Task**:
Implemented the full Albums & Tracks Catalog feature slice for Phase 1.5, spanning 6 command/query features, their HTTP endpoints, and 35+ xUnit integration tests.

**Features Implemented**:
1. `CreateAlbum` — artist creates an unpublished album; primary artist (Order=0) + genres attached.
2. `AddTrackToAlbum` — primary artist adds metadata-only track + pending `TrackFile` placeholder; auto-increments `TrackNumber` and `TrackCount`.
3. `EditTrackMetadata` — primary artist patches title, duration, genres, and featured artists; junction tables sync atomically.
4. `PublishAlbum` — toggles `IsPublished = true`; guards empty album, already-published, and non-primary-artist access.
5. `GetAlbum` — retrieves single album with ordered tracklist, artist attributions, and genres; Redis-cached (30 min).
6. `GetNewReleases` — top-N published albums by release date; Redis-cached (15 min).
7. `ListAlbums` — paginated, filterable (title, genre, artist, published status, album type), and sortable; Redis-cached (10 min).

**Architecture Notes**:
- All command handlers use `CatalogDbContext` (write); all query handlers use `CatalogReadDbContext` (read, no-tracking).
- `AlbumArtist.Order = 0` is the primary artist convention (matches existing schema, not a boolean flag).
- Endpoint security: Create/AddTrack/Edit/Publish require `Artist` role; Get/List/NewReleases are public.
- Mapster adapters used for Request→Command in `CreateAlbum` and `ListAlbums` endpoints.
